# Data Provenance Audit

_Last verified: 2026-07-24_

This document classifies every user-facing route in the platform by whether the
data it displays is **Real** (persisted in Lovable Cloud and generated by real
users), **Reference** (sourced from an external document with a stated caveat),
**Fabricated** (illustrative content hardcoded in the component for demo
purposes), or **Mixed** (a real backbone with illustrative filler around it).

All `Fabricated` and `Mixed` pages render `<DemoDataBadge />` in their header so
viewers can see the distinction in-app.

## Summary

- **Real, DB-backed (10 surfaces):** Login, Signup, Contact, Onboarding LOA,
  Admin Authorizations, Admin Members, Admin Audit Log, Compliance Analyzer
  (presets), Load Profile Analyzer (inputs), and the auth-role hook.
- **Reference data (3 surfaces):** Utility Coverage, Utility Provider Map,
  Glossary — sourced from user-provided docs and `src/data/utilityProviders.ts`
  (which itself carries an in-file caveat to verify against EIA Form 861).
- **Fabricated (everything else, ~70 surfaces):** All dashboards, mission
  control, operations boards, admin CRM/invoicing, portfolio views, SIR
  workspace, project workspace, UCI route pages, closeout, feasibility, mobile
  studios, and the McDonald's executive demo.

Nothing on the platform reads from a real AHJ portal, a real utility API, or a
real client project system today.

## Reference data caveats

- `src/data/utilityProviders.ts` — real utility names, real corporate contacts,
  real URLs; **SLAs, health ratings, and territory classifications are
  Commun-ET's own estimates**. The file header explicitly says: _"verify
  current service territories against EIA Form 861 before external use."_
- Glossary terms are sourced from the user-provided AEC glossary document. No
  edits were made to definitions.
- Approved marketing metrics ("90% reduction, 50+ jurisdictions, 12 modules,
  8 agents") live in project memory. They are talking points, not measurements
  from live pilots.

## How to verify in-app

1. Any page rendering `<DemoDataBadge />` is fabricated. Hover the badge for
   the standard disclaimer copy.
2. The 10 real, DB-backed pages above render no badge. Data on those pages is
   what the user has entered or approved through Lovable Cloud.
3. Reference pages show a "Reference data" caveat block or link, and are backed
   by `src/data/utilityProviders.ts` or the user-provided glossary/UCI docs.

## Non-goals

- This audit does not remove or rewrite any fabricated dataset — the demo
  surfaces remain intact for the McDonald's presentation and internal review.
- Wiring the fabricated pages to real data sources is tracked separately in
  `docs/lovable-ui-backlog.md`.
